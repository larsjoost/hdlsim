# Real-world source corpus

Third-party VHDL/Verilog sources fetched from the internet, used as parser and
front-end test fixtures (`../corpus.rs`). Each file is used unmodified; licenses
are in `licenses/` and each file header retains its upstream copyright notice.
`vhdl/` is compiled as one library (`work`, plus `neorv32`/`unisim` aliases); `vhdl-vunit/` is a
second, separate library (`work` + `vunit` + `vunit_lib`, plus `osvvm` mapped to `vhdl/`) so VUnit's
own `work.*`/`vunit_lib.*` references resolve within the group, its OSVVM dependencies come from
`vhdl/`, and same-named GHDL corpus units (e.g. `types_pkg`) don't collide.
`vhdl-osvvm/` holds the OSVVM *model* libraries (AXI4, OSVVM-Common, UART, Avalon-ST, Wishbone,
Ethernet, DpRam, SpaceWireMonitor), one corpus group per repo subproject
(`vhdl-osvvm/<repo>/<sub>`, e.g. `axi4/Axi4`), so each subproject's testbench entity (one
`TestCtrl` per testbench variant) stays unique within its group's `work`; a repo's
`testcases` dir is merged into its sibling `testbench` group (its architectures are
`of TestCtrl`, whose entity lives in the testbench dir). Each group registers its
own dir as `work`, every repo's `src` tree under the repo's logical library name (`osvvm_axi4`,
`osvvm_common`, …), and the OSVVM core (`osvvm`) mapped to `vhdl/`. Files that declare a unit name
duplicated within a subproject (the per-variant `TestCtrl`/`TbAxi4`/… copies and their
architecture files) are excluded, as are `deprecated/` trees, `${...}` templates, non-UTF-8
sources, and `wishbone/src/WishboneManager_v0.vhd` (legacy file whose concurrent conditional
assignment omits the trailing `else` waveform *and* the `;` — not legal VHDL). In `cosim/`,
only the GHDL variant of the per-simulator `OsvvmVprocPkg` packages is kept (`attribute foreign
... VHPIDIRECT`), and in `cospcile/` the `testbench/thirdparty/alterapcie` Altera IP is excluded
(needs Altera vendor libraries).

The tests assert: every file lexes and parses without errors (the CST is
lossless), and a full `check` (parse + lower + resolve) runs to completion
without panicking, rendering any diagnostics rustc-style. Each language
directory is compiled as one library (the directory is registered under the
logical `library` names its files declare, e.g. `-L neorv32=<dir>`), so
cross-file design units resolve on demand — the same way a user runs
`hdlsim check -L neorv32=rtl rtl/*.vhd`. Files that use language features
outside hdlsim's current subset are expected to produce *diagnostics* (that
is what the check is for) — never a crash.

## expected.json — per-file progress tracking

`expected.json` records each file's current status: `clean` (compiles+lowers
with zero *error* diagnostics) or `diags` (parses clean, still hits unsupported
constructs). `corpus_files_meet_their_recorded_status` asserts every file
reaches at least its recorded status, so a fix only moves files up: promote the
entry in `expected.json` in the same PR that fixes the file (regression below
the recorded status fails CI). New corpus files must be added to `expected.json`
explicitly — regenerate with `HDLSIM_UPDATE_CORPUS_EXPECTED=1 cargo test -p hdlsim
--test corpus`.
